# 探索的分析2：同じ条件の run の間で、選ばれたオラクルはぶれるか

この分析は事前登録（`preregistration.md`）に含まれていない。
探索的な分析として、事前登録した分析とは分けて報告する。

## 経緯

実験者は記事の中で、「依頼に仕様が示されていないとき、AI が推測するオラクル（検証の基準とする性質）はぶれる」と述べている。
run-01〜run-03 では選ばれた性質がそれぞれ違ったが、これらは条件（モデル、最初の発言、使えるツール、対話の仕方）がそろっていない。
そこで、同じ条件の3回の間で比べる。

この方法を決めた時点で、分析者（ハーネス側のセッション）は run-02（A の1回目）と run-03（A2 の1回目）の内容を読んでいる。
run-04 以降の内容は読んでいない。
分析者は仮説（`preregistration.md` 1章）と、実験者の上の主張を知っている。

## 比べる区間

同じ条件の run どうしは、最初の発言、イメージ、モデル、手順が同一である。
ハーネス側からの最初の入力より前は、被験側への入力が完全に一致するので、この区間の違いはサンプリングによるものだけになる。

- **区間**：最初の発言（U1）の後から、ハーネス側からの最初の入力の直前まで。ハーネス側からの入力とは、人間側の2番目の発言（U2。「お任せします」か固定発言）、または選択肢の UI への回答（AskUserQuestion の結果）のうち、早いほうである。
- **区間内の被験側の行為**：表示テキスト、道具の呼び出し（書いたファイルや実行したスクリプトを含む）。

## 抜き出すもの

区間内で被験側が検証の基準として立てた性質を、次の2種に分けて抜き出す。

- **(i) 候補**：検証の候補として発言で挙げたが、区間内には検証に着手していない性質。
- **(ii) 着手**：区間内に、その性質を表すファイルやスクリプトを書いた、または実行した性質。

各性質について、事前登録の「性質ごとの表」の列1〜3（名前、被験側の説明文の原文、形式的な命題の原文）を記載する。
区間外で初めて出た性質は、この分析には含めない。

## 分類（解釈を含む）

各性質に、次の2つの分類を付ける（複数可）。
分類の語彙は、この文書のコミット時点で固定する。

- **対象**：出力（`lib/publishing.js`）、パーサー（`peg_src/`、`parse`）、走査（`lib/traversing.js`）、parse と publish の組（構文木全体）、その他（原文で記載）
- **内容**：往復、逆関数または単射、例外が出ない（全域性）、網羅（すべてのノードの訪問など）、停止性、受理と拒否、文法の性質（曖昧さなど）、その他（原文で記載）

あわせて、着手した性質ごとに手法（Lean、TLA+、Z3、全列挙、ランダム試験、既存テスト、その他）を記録する。

## 集計

- 条件ごとに、3回それぞれの（対象, 内容）の組の集合を並べる。候補と着手は分けて並べる。
- 3回の間で、集合が一致するか、一部重なるか、重ならないかを記す。
- 同じ条件の2回で着手した性質の集合が異なれば、その条件では「区間内に選ばれたオラクルがぶれた」とする。3回とも一致した場合も、そのまま報告する。
- 分類の判定は分析者の解釈を含む。読者が検証できるよう、すべての性質を原文つきで一覧にする。

## 解釈上の注意

- 1条件あたり3回しかないので、ぶれの頻度や大きさは推定できない。示せるのは、ぶれが起きるかどうかだけである。
- 分類の粒度によって、一致かどうかの判定は変わりうる。粗い分類（対象だけ）と細かい分類（対象と内容）の両方で集計する。
- 本試行のモデルは Opus 5.5 だけである。
