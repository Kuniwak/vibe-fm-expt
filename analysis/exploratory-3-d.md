## 対象と方法

独立の符号化の対象は、主張476行と発見82件である。

- 2つの読みの分類（両方の読みで内側、強い読みでだけ超える、弱い読みでも超える、変種）は、どちらかが段階2〜4の検知の主張とした176行のうち165行で一致した。
- 分かれた11行のうち2行（run-28 C76、run-30 C49）は、強い読みの差である。元の作業者は「超えた」、独立の作業者は成果物のコードで構造を確かめて「なし」とした。

## 結果

### 段階2〜4の検知の主張（表1〜表3）

- 段階2〜4の検知の主張は、元の作業者で176行である。そのうち141行は、特定の変種（または実在の違反）を主語にした主張だった。
- 種類を主語にした主張（「種類」「決められない」）は35行で、そのうち「強い読みでだけ超える」が24行（両方の作業者が一致したのは22行）、「両方の読みで内側」が11行（同じく11行）、「弱い読みでも超える」は0行だった。
- 「強い読みでだけ超える」24行のうち22行は、同じ発言に明示の限定文があった（表2）。
- 読み手の最初の読みは、元の作業者の主語の判断とほぼ一致した（表3）。「変種」を主語にした141行を、読み手は1行も強い意味に取らなかった。この読み手が変種の結果を種類全体に広げて読んだ事例はない。ただし読み手は1人であり、読み手一般について言えるものではない。
- 読み手と独立の作業者の最初の読みが分かれたのは、run-31 の4行（C113、C115、C116、C118）だけである。被験側は、判定の表の直前で「検知できる」を「確かめた範囲だけ」「保証ではない」と定義していた。読み手はこの定義を読んで弱い意味に取り、独立の作業者は強い意味に取った。規則（追記の1）は限定を `gap_strong` に及ぼさないので、この4行は「強い読みでだけ超える」に数えている。

### 段階別の差と発見（表4、表5）

## 未解決の点

- 主語の境目（種類名が見出しにあり、文の主語が変種の行など）は、作業者の判断が分かれうる。各 run の `boundary.md` に残した。
- `limit_in_message` の「明示の限定文」に、手順を述べた文（「1つずつ埋め込みました」）や、手作業の確認の範囲を述べた文が入るかは、作業者の間で揃っていない。
- 構造の議論で強い読みを「なし」とするとき、言語の実行モデルの知識（同期のループはタイマーで止められない、など）にも依る場合を、成果物で確かめたと言えるか（run-28 C55、C88）。
- `later_human_table` の「合う」は、規則（追記の7）の文から意味が1つに決まらない。入力が表に照らしても食い違いとして残ることとも、食い違いの所在と修正の向きまで表と一致することとも読める。作業者の値はこの読みの差で割れており（s2-y の Y3 など）、実験者の判断で、どちらにも解釈せずに作業者の値をそのまま残した（2026-11-19）。この列は数の比較や結論には使わない。事実として言えるのは、W3、W4（s2-d）では、被験側が段階1で publish の誤りと断定して publish 側を直したのに対し、後に渡した表に照らすと食い違いの所在は parse の側にあることである（`bundling-notes.md` の4、30 境界例 B24、32 境界例 B15）。
- 検知の主張の行の `gap_object` と `intent_check` の書き方は、作業者の間で揃っていないが、検知の主張の行で `gap_object` を「超えた」とした作業者はいない（s2-d 176行、s2-y 261行）。`intent_check` は表6だけで使う。表1〜表5と結論に関わらないため、台帳は書き換えない（2026-11-19）。
