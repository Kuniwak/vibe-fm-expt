# run-06 独立の符号化：迷った行

対象は #1〜#15（固定発言は作業中の割り込みとして届いたため）。入力の主張はすべて #5 と #6 にある。

## C25（「**3. publish によって意味が変わる**」）

- 評価の語（バグ、壊れる など）はない。変更2の1 では挙動を述べただけの文は断定に数えない。
- 一方、証拠は自作のオラクル（meta を除いた AST の一致）への不一致だけで、文面は「意味が変わる」と述べている。入れ子の順が意味を持つかは作者が決めることなので、オラクルの項目で「超えた」（不一致側）とした。
- 「なし」と読む余地もある。「意味が変わる」を評価の語とみるか、挙動の記述とみるかで値が分かれる。

## C19（「後置の ? / ! が入れ子になると、publish の出力を再パースできない」）

- 範囲は一般の形で述べている。証拠は、長さ3以下の網羅と長さ12以下のランダム検査で出た形の集計と、publisher の実装の読解（常に前置で出す）。
- 原因の説明が一般の形を支えるとみて「なし」にした。有界の検査から一般の形へ広げた点を範囲の超過と読む余地はある。

## C27（P2「全モード・全入力で違反ゼロ」）

- 同じ発言の同じ節に「試した範囲では反例がない」という限定があるので、範囲は「両論」とした。
- 「両論」のときに gap_direction を何にするかは規則にない。超える側の向きとして「成立側」と書いた。

## C28（「上の3パターン以外では、P1 と P3 の違反は見つかりませんでした」）

- claim_kind を「成立」にするか「限界」にするかで迷った。違反が出なかったことを報告する節の行なので「成立」、holds_claim は yes とした。
- 被験側は、不一致の分類のうち奇妙な形を先頭6件までしか表示していない（call 7）。分類が3パターンに収まることを、被験側は確かめていない。
- check.js は再パースに失敗した入力で continue し、P3 を検査しない。主張は3パターンを除いているので、差は「なし」とした。

## 発見 F3、F5 の asserted_defect

- F3（traverse が y を訪問しない）：その行自体は「P3 の違反です」で、挙動の記述にとどまる。ただし項目1（「AST が壊れる(重大)」「バグ1」）の一部として述べられているので、yes #6 とした。
- F5（keyof A ? → keyof ?A）：項目2の「似た例」として、「見つかったバグ」の節にある。修正案の「バグ2・3(publisher で…)」とは原因が違う（文法側）。節の見出しを及ぼすかで値が分かれる。

## F6 の oracle_class

- 自作（AST の一致）だけとした。
- リポジトリのテストは、後置を前置に正規化する出力（'Object!'→'!Object'）を期待している。この不一致の原因になる挙動をリポジトリ内のオラクルが期待しているとみれば、【リポジトリ内のオラクルと逆】に当たりうる。ただ、`??!` そのものの期待値はテストにないので、印はつけなかった。
