## 確かめられなかった点

- 乱数生成の重複の数は、`inputs:` 行の差から出した。重複を直接数えた出力は記録にない（B2）。
- `peg_src/jsdoctype.pegjs:163`：修正前の文法（回収したリポジトリの `git show HEAD~2:peg_src/jsdoctype.pegjs`、読むだけ）では、`name: tokens[3]` は 165 行目。「163 行」がどこを指すかは決められない。
- call 53 のカバレッジは、grep で publishing.js の行と ERROR 行だけを表示している。All files の行は表示されていない。
- call 30 で背景に回した Z3 の長さ12の実行は止められ、結果は出ていない。
- `keyof !` が修正後に構文エラーになること、単独の `?A[]` の AST、修正前の `keyof ?` の parse 結果は、記録の出力からは確かめられない。ハーネス側では再生していない。
- `npm run formal` の終了コードと所要時間、`npm test` を通しで実行した場合の結果。
- TypeScript の優先順位（C27、C62、F8）は、記録の外の知識による。

## 規則で決めきれなかった点と改善案

- 評価の語の一覧に、「一貫していない」「往復が壊れる」が入るか（B33、B37）。
- 「尋ねた(b)」を、問いの性質を含む検査全体の通過の主張にまで及ぼすか（B35）。
- issues の 1 の定義（gap と solo_gap の違い）に、発言単位の判定だけが変わった行（B26）を含めるか。
