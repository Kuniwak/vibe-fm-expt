## 確かめられなかった点

- C28〜C30、F1：`"\n"` を実コードで読んで出力し直すと `"\\n"` になるか。記録に実行がなく、ハーネス側は再生しない規則なので確かめていない。
- C8b：最終版の Quoting.lean の定理が依存する公理。`#print axioms` は書き換え前の版にしか実行されていない（回収したファイルに `sorry`、`admit`、`axiom` の語がないことだけは grep で確かめた）。
- C21、C20a：call 20 のサンプルが具体的にどの文字列を生成したか。seed の記録がなく、出力は件数だけ。
- モデル（escapeJS、unescapeJS、pegBody、replace2、traverse）が JS と PEG.js の生成コードの振る舞いと一致するか。被験側も機械的には照合しておらず、台帳では仮定として書くにとどめた。
- 4つの文法規則のうち FilePathExpr と RecordTypeExprEntryKey は、実コードでのサンプルの対象に入っていない（call 20 は STRING_VALUE と MEMBER だけ）。

## 規則についての気づき（v1 のもの。変更1で 1〜4 は扱いが決まった）

- 一文の中に成立と非成立が混じる文（C29〜C30「値は同じ…が、元の入力文字列は保たれません」）や、否定の形で実コードの振る舞いを述べる文は、`holds_claim` の yes／no と「否定の主張は差なし」の規則の当てはめが決めにくい。「限界の表明（検査が示していないこと）」と「否定の形の振る舞いの主張（コードがこうならない）」を分けて扱う規則があると決めやすい。
- 「同じ発言の中の限定は、その発言の中の文すべてに及ぶ」の規則では、冒頭の「モデルについて」が箇条の全行に及ぶため、対象の差がほとんど「なし」になる。箇条の行のように単独で引用されうる文について、別の扱いを設けるか検討の余地がある。
- 成果物なしの主張の差の値（「不明」か「超えた」か）が規則に書かれていない。この run では「不明」とした。
- 被験側が不一致と呼ばずに報告した差（「非対称性」）を発見に含めるかの基準があるとよい。
