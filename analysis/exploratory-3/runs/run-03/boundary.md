### C17a の詳細（変更2の2）

- 主張：「なお、`A?` が `?A` に変わるような単純な正規化は、構文木が同じなので問題にしていません。」（#1）。
- 採用した符号：オラクル「なし」。リポジトリ内のテスト（tests/test_publishing.js の 'goog.ui.Component?' → '?goog.ui.Component'、'Object!' → '!Object'、'module:foo/bar?' → '?module:foo/bar'）が、後置の nullable を前置で出力することを期待している。
- 記録の順序：被験側は #1 の時点でこのテストを読んでいない。
  - #1 より前の呼び出しは call 1〜5 である。中身は、ファイル一覧と package.json、npm test の末尾25行（traverse のテスト名とカバレッジの表だけ）、lib/publishing.js の先頭80行と index.js、check.js の作成と実行、publishing.js の grep、node -e による例示。
  - test_publishing.js の nullable のテストを初めて読んだのは、U2（03:12:56）の後の call 6（03:13:00）と call 7（03:13:03）である。
  - #1 で挙げた根拠は「構文木が同じなので」という自作のオラクル（meta を除いた構文木の一致）だけである。
- 別の読み方：変更2の2の「自作…のオラクルを満たすことを根拠にした：超えた（成立側）」を当てると、「超えた」になる。変更2の1は「読んでいたかは問わない」と明記するが、変更2の2には同じ明記がない。
- 範囲についての留保：「のような」は F4 の AA...→...AA（後置の可変長を前置で出力）も含みうる。これを期待するリポジトリ内のテストはない（test_publishing.js の可変長のテストは、前置形の入力 '...number' などだけ）。この部分は、根拠が自作のオラクルだけになる。

## 確かめられなかった点

- npm test（call 12）は grep で絞った出力で、終了コードが表示されていない（C21a〜d）。call 2 も tail -25 だけ（C7a〜c）。
- 列挙の被覆は被験側が確かめていない。tried=1503576 が 4×(42+42²+42³)+4×300000 と一致することは、台帳作成時に計算で確かめた。
- check.js は不一致を種類×モードごとに最大8件しか記録しないので、修正前の不一致の全体は分からない。
- 被験側は文法ファイルを読んでいない（C15、C23、C32）。
- ?A! の構文木は出力されておらず、publish の出力から読んだもの（C12、F2）。
- git の HEAD が実験開始時の状態と同じことは、fs-diff.txt からの間接的な確認にとどまる。
- npm test の tail -25 の出力に、ほかのテスト名が含まれていたかは記録の出力どおりに読んだ。出力には traverse のテスト名だけが見える。
