## 列の意味についての迷い

- `claim_kind` の「限界」と「その他」：検査の制約（Z3 の unknown、長さ 5 で打ち切り）は「限界」とした。道具の挙動の原因の帰属（#9）と検査の経緯は「その他」とした。
- `gap_direction`：差の値が「不明」だけの行（C1、C12、C16、C25）は「—」とした。規則は「超えた項目がない」場合を「—」とするが、「不明」の扱いは決まっていない。

## 確かめられなかった点

- escape_z3.py のモデル（JS の `replace(/lit/g)` を位置ごとに展開したもの、字句規則）が実コードに忠実か。ハーネス側では検めていない。被験側は反例を実コードで再生した。unsat の結果は再生できない。
- escape_enum.js の4文字の字母が同値類を覆うという被験側の議論。誰も確かめていない。
- 列挙の入力（56,684 件）が対象の構文を代表しているか。被覆は誰も確かめていない。
- リポジトリ全体で `?Foo[]` の優先順位を決める記述があるか。README・テスト全体は、`permissive` と一部の文字列だけを grep した。
- TypeScript で `keyof` が予約語か、`keyof ?` が無意味な入力か（外部の仕様。確かめていない）。
- 成果物は実行していない（規則どおり）。数値は記録の出力から読んだ。
- 記録の道具の出力を読むとき、1件あたり 8,000 字で切った写しを使った。grammar の全文（call 4, 5）など長い出力は、必要な行だけを読んだ。
