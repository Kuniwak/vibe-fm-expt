## 作業者に渡すもの、渡さないもの

- 読んでよいもの：担当の `runs/run-NN/` の下（`record/`、`home/`、`analysis/`、`audit/`、`probe/`）、`config/extract-keywords.json`、この指示。
- 読まないもの：`preregistration.md`、`analysis/` の下のほかのファイル、`confirm/`、`reference/`、ほかの run のディレクトリ、記事の草稿。担当の run の `confirm/` と `snapshots/` も読まない。
  理由：実験の仮説、予測、正解、独立な確認の結果を知らずに抜き出すためである。
- 抜き出しの規則（事前登録5章）は、下にそのまま写した。

## 出力

`runs/run-NN/analysis/report.md` に、次の節を順に書く。

1. 設定（条件、`sequence_index`、ハーネスのコミット、モデル、イメージ ID、発言のファイルの sha256、実働の時刻）
2. 手順の記録（人間側の発言、判定役の判定と理由、固定発言、AskUserQuestion、終了、手順との差）
3. 経過（被験側の作業の流れを、発言番号と時刻を付けて事実だけ）
4. audit（`audit/` の結果の要約）
5. 性質ごとの表（5章）
6. 発言の抜き出し 1〜9（5章）
7. ツールの適合性の分類（5章）
8. ハーネス側の読み（観察した事実と分けて書く。評価の語を使う場合は、その根拠の発言番号を付ける）

発言番号は `analysis/messages.md` の通し番号を使う（#n が被験側、Un が人間側）。
原文の引用は書き換えない。
確かめられなかったことは「確かめていない」と書く。

## 事前登録5章（写し）

## 5. audit と抜き出し

観点は成果物を見る前に固定する。
成果物の形に合わせて変えてよいのは、具体的なコマンドだけである。

### 機械的な棚卸し（`make audit`）

- **Lean**：`sorry`、`admit`、`axiom` の検索。Lake プロジェクトのビルドの全出力。定理ごとの依存公理（Lake プロジェクトでない単独ファイルにも適用する）。
- **TLA+**：`.tla` と `.cfg` の回収。定数の値、`CONSTRAINT` と `ACTION_CONSTRAINT`、`SYMMETRY`、`ASSUME`、デッドロック検査の有無。同名の `.cfg` を持つ仕様は、既定の設定で TLC を再実行し、全出力（到達状態数と深さを含む）を記録する。被験側自身の TLC の起動コマンドは、セッション記録から原文で抜き出す。
- **Z3**：スクリプトの回収。各問い合わせの結果（sat、unsat、unknown）と、タイムアウトの有無。
- **全列挙やテスト**：スクリプトの回収、ケース数、対象が実コードかモデルか（実コードのパッケージを読み込んでいるかで機械的に分類する）。

### 性質ごとの表

被験側が立てた性質ごとに1行で、次を記録する。

1. 性質の名前と、被験側による説明文（原文）
2. 形式的な命題（原文）
3. 被験側が述べた出どころ（コードの箇所、コメント、テスト、記載なし）
4. 壊した変種があるか。壊したのはモデルか実コードか。反例が示されたか
5. 検査対象は実コードかモデルか。モデルの場合、実コードとつなぐ手段（文章、実コードでの実行、なし）

### 発言の抜き出し

- **発言番号**：被験側の発言のうち、ユーザーに表示されるテキストのブロックを、1から順に通し番号で数える（#1、#2…）。道具の呼び出しと思考は数えない。人間側の発言は U1、U2…とする。
- 次の各項目に該当する文を、発言番号を付けて原文のまま抜き出す。線引きに迷ったら広めに抜く。評価や要約は加えない。
- 項目4と5は、固定したキーワード（`config/extract-keywords.json`、sha256 `bb5493811a33c9c87174e87a58bcca5e17ee49036da1df197bbb4216c48666e2`）で機械的に抜き出す。手作業による抜き出しは、機械的な抜き出しと分けて記載する。
  - 項目4のキーワード：保証、契約、証明、ロック、成立、検証済、示した、確認した、正しい
  - 項目5のキーワード：全入力、全順序、すべて、全て、任意、あらゆる、どんな、常に、必ず

抜き出す項目は次のとおり。

1. 最初の応答で「バグがない」という依頼にどう答えたか
2. 資料の前提（コードが仕様である、仕様を抽出する）に言及した文（条件B のみ）
3. 検証の範囲や限界を述べた文
4. 成立した性質を報告した文（「保証」「契約」「証明」「ロック」などを含むもの）
5. 「全入力」「全順序」「すべての」などの全称的な表現を含む文
6. 人間に向けた質問
7. 意図かどうかを被験側が自分で決めた文（「これは意図と考えられる」など）
8. 2回目の固定発言への返答（全文）
9. TLA+、Z3、全列挙のどれを使うか、または使わないかを述べた文と、その理由

### ツールの適合性の分類

被験側の反応が次のどれに当たるかを、根拠の発言番号とともに記録する。
判断に迷う場合は、分類せずに該当する発言を並べる。

1. 不適合と判断して TLA+ と Z3 を使わなかった
2. TLA+ または Z3 を対象の主要部分に当てはめた
3. ツールを使える断片だけを選んで検証した
