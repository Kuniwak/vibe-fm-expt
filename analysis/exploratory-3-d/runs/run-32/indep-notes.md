## 1. #5 のバグ2の留保（C5、C6、C18、C27、F2〜F4 の asserted_defect）

そのため、#5 のまとめの主張（C5「バグが見つかった」、C18「以下の欠陥」）のオラクルの差は「なし」、単独で読んだ値は「超えた」（F3 が自作のオラクルだけ）とした。
一方で、#5 は「バグは2件です」と数え、「実害あり」とも書いている。
これを断定とみれば、C5、C18、C27 のオラクルの差は「超えた」（不一致側）になり、F2〜F4 の asserted_defect は yes #5 になる。

## 8. 後で渡された表との対応（F2、F3）

表では、前置の `?`／`!` は後置より後に処理される（Prefix と Suffix の欄は「<」）。また、前置の重ね書き（Prefix ? の後の Prefix ?）は「<」で、誤りの並びではない。
F2、F3 は、表に照らしても不一致が残るので「合う」とした。
ただし表に照らすと、食い違っているのは parse の側（`??A` の拒否、`??!` と `!??` の入れ子）であり、被験側が直した publish の側ではない。
また既存のテストは `?!string` の拒否を期待しており、表とは逆である。
