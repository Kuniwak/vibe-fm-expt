## 確かめられなかった点

- Oracle.lean が表のすべての欄を被験側の述べた解釈どおりに読んでいるか。作業者は数か所を照らしただけで、プログラムは実行していない（実行しない約束のため）。
- 種類1の照合の数（43,080 件など）と分類の件数は、被験側の出力（call 63・64・73）から読んだもので、作業者は数え直していない。
- コミット 5fa673a の `PrefixOptionalTypeExpr` が前置 `=` の規則であるか（被験側も作業者も確かめていない）。
- #5 の「npm test も通っています」の時点の通過件数（出力が途中まで）。
- grammar-inputs.js の生成が「文法から」の導出として文法を覆っているか（列挙・生成の被覆は誰も確かめていない）。
- 規則で決めきれなかった点の要約：
  - 段階2の文面を送った行の `stage` が3であるため、段階2に属する発言が生じない（B1）。D 系では、段階2の文面への返答を段階2と呼ぶか3と呼ぶかを規則に書くとよい。
  - 否定の検知力（「検知できない」）に変更4の7を当てるか（B8）。
  - 人間がオラクルを与えた後の成立の主張の `intent_check` の値（B10）。値「人間が与えた」を足す案がある。
  - コミットの件名をリポジトリ内のオラクルに数えるか（B15）。
  - 変更4の7の値B と変更2の4の両論が同時に当たる場合の扱い（B18）。
  - 同じ文の発言が大量に繰り返された場合に、作業の報告として台帳から外してよいか（B2）。
