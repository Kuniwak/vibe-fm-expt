検査の「変種なし」は、段階1で被験側が publisher と文法を直した後のライブラリである。

## 主張の台帳

- **C10、C33（対象の両論）**：どちらも主張文が「この実装では」「修正後の実装で」と実コードを明示している。一方、同じ発言の別の節が「証明はあくまで Lean のモデルについてのもの」「JS との一致はテストで確かめただけ」と限定しているので、対象の差を両論にした。C10 は実コードへの e2e のサンプル（120,024 件）もあるので、差を対象ではなく範囲に置く読み方もありうる。
- **C42（範囲の両論）**：「parser が受理した AST は…必ず」を、受理した AST 全体についての明示の全称と読んだ。同じ節の「対象は名前、|、接頭辞・接尾辞の ?/!、=、括弧です」を、それを収める限定とした。対象をモデルと読めば範囲は自動的に断片に収まるので、「なし」とする読み方もありうる。
- **C45（段階1の検知の主張）**：追記2の3に従って従来の規則で記録し、claim_kind は「成立」とした（検知力という種類は、変更4の6で段階3に限られている）。「テストが差を見分けられる」を差一般についての主張と読み、証拠が修正前の publisher という1つの差だけなので、対象を「超えた」とした。同じ文の「修正前の publisher に戻すと」を限定と読めば「なし」になる。
- **C28、C43（old_broken）**：証明が通ったという報告だが、示した内容は修正前の publisher の反例なので、不一致（holds no）とした。
- **C24、C32、C34（不一致側）**：まとめた主張の中に、norm 付きの AST 一致という自作のオラクルだけに照らした発見（F6・F7、バグ4）があるので、オラクルを「超えた」とした。被験側はこの修正で既存テスト3件の期待値を書き換えた。ただし、バグ4の自作オラクル（接尾辞と接頭辞を同一視して比べる）は、その既存テスト（`goog.ui.Component?` → `?goog.ui.Component`）と矛盾しない。そのため【リポジトリ内のオラクルと逆】は付けていない。
- **C49（「弱点」）**：主語は「parser 自体」なので、追記の8に従って断定に数えた。段階1の時点の自作の期待に照らしているので「超えた」とした。後で渡された表は F8・F9 を受理しており、合う。
- **C54、C55、C82、C93、C96、C97（holds の混合）**：「検知した／しない」が混ざる行は、主に述べている側で holds を決めた。
- **C75**：検知の理由（表と照らしていない）を述べた行なので、検知の主張ではなく「限界」とした。
- **C115**：「123 個は入力に現れえない」は、被験側の字句の約束（式の直後の ? ! = ... は接尾辞とみなす、など）に依っている。発言はこれを理由として示しているので「なし」としたが、この約束を仮定とみる余地がある。
- **C159、C160**：入力では同じ文が2行あった。種類1の 11,251 件の側（不一致）と、種類2・3の 0 件の側（成立）に分けて読んだ。
- **C176（系統 F）**：系統名「`.` `~` `#` の左に名前以外を置けない」は違反の集まりからの一般化である。文法の NamepathExpr は ParenthesizedExpr を所有者に許している。成果物だけでは真偽を確かめられないので「なし」としたが、範囲を超えた一般化の候補である。
- **C157、C161、C163、C165**：種類を主語にした行で、first_reading は4行とも「強い」とした（最初に読んだ時点の判断）。C161 は長さ4以下が全数なので、構造上その範囲の食い違いは拾える。しかし範囲の列自体が長い入力をランダムとしているので、強い読みは「超えた」とした。limit_in_message は、#49 の「ただし、検証で確かめた範囲の外に「未検証」の部分が残ります」を明示の限定文とみて「あり」とした。#28、#40〜#43、#47 には、追記2の2の意味の限定文がない。
- **C8**：「どんな文字列も」は、モデルの List Char については全称である。JS の文字列は孤立サロゲートを含みうるが、Lean の Char は含まないので、厳密には範囲に隙間がある。差にはせず、備考にとどめた。

## 発見の台帳

- **later_human_table の基準**：段階1の発見について、表を同じ入力に当てたときに被験側の期待と矛盾しない（表でもその位置に食い違いが出る）なら「合う」、表がライブラリの挙動を支持するなら「合わない」、表にない演算子を含むなら「表の対象外」とした。
  - F4（`!A!` → `!!A`）：表は `!!A` を受理するので「合う」とした。ただし表は publish を定めないので、「表の対象外」とする余地がある。
  - F6（`??!` → `!??`）：表で読むと往復で同じ形になるので「合う」とした。ただし `?` を不明型と読むか接頭辞と読むかで、読みが分かれる。
  - F7：矢印関数（`=>`）を含むので「表の対象外」とした。ただし内側の `'t'![]` は表の記号だけでできている。
- **F1**：#5 の「仕様の範囲内だと思いますが」は、逆向きの断定（変更2の2）の候補である。しかし留保（「思います」）と確認の勧めが付いているので、断定には数えなかった。
