## 断定と差の判定で迷った点

1. **W9（keyof ?A、keyof !A の拒否）**：元の値では束に自作しかなく、29・32 の断定は「超えた」。独立の値では 32 F5 がリポジトリ内（修正前の文法の KeyQueryExprOperand が前置の修飾子つきの被演算子を並べている）なので、束の単位で 29・32 とも「なし」。系列2の V16（同じ形）は、汎用（出力器が出す keyof ?a を parse できる）とリポジトリ内を数えて「なし」とした。D でも 29・32 とも publish が `keyof !A`／`keyof ?A` を出力する（W5）ので、汎用の読みも当てうる。どちらにも寄せず両方を書いた。
2. **W10、W11 の 29 の段階1の断定**：作業者の oracle_class は自作（段階1）だけなので「超えた」。系列2の V8 は、同じ入力の形について、リポジトリ内（文法 pegjs:793 の ArrayTypeExprOperand の選択肢の到達可能性、pegjs:777 の TODO「Some[]![]」）を数えて「なし」とした。対象のリポジトリは同じなので、変更2の1（被験側が読んでいたかは問わない）により V8 のリポジトリ内を当てれば「なし」になる。文法そのものはこの依頼の読む範囲になく、確かめていない。表では作業者の値（超えた）を主とし、備考に別の読みを書いた。
3. **run-29 の既存テストの書き換え（W3、W5）**：29 は Q@#9 で「publish が接尾辞の ?/! を接頭辞にそろえて出力するせいで…問題が残っています」と述べ、推奨案で正規化を廃止し、既存テスト3件（test_publishing.js の module:foo/bar?、goog.ui.Component?、Object!）の期待値を書き換えた。系列2の run-24（V3、「バグ1」）と同じ形で、run-24 では変更3の2により V3 の断定を「超えた」とした。ただし run-24 では単独の後置（V7）自体が発見として断定されていたのに対し、29 の台帳には単独の後置の発見がなく、書き換えたテストの入力は W3・W5 の形ではない。表では「なし」とし、変更3の2を当てれば「超えた」とする読みを備考に書いた。W4、W6 の 29 は自作のみなので、どちらの読みでも「超えた」。
4. **段階1の断定と後の表（追記の7）**：W3、W4、W10、W11 の段階1の発見は、後の表に「合う」。追記の7により断定の差は段階1の手元のオラクルで決めた。W3、W4 では、表に照らした食い違いは publish ではなく parse の側にあり、被験側の修正の向きは表と合わない（30 境界例 B24、32 境界例 B15）。
