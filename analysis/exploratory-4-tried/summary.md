## 筆者の読み

### 1. 何も試していないことを「成り立つ」と言った主張がある

対象のコードの性質を述べているのに、それを判定した実行が表1に見つからない主張があった。
2人の作業者のどちらかが「見つからない」と書いた行は18行ある（`selected.md` の基準1）。
そのうち15行は、2人とも対応する実行を1つも挙げなかった。

- 対象が副作用のない純粋関数だという主張（run-23 の C1、C12、C16、run-26 の C7）。どれも TLA+ を使わない理由として述べられている。
- Lean のモデルが元のコードを正しく写しているという主張（run-18 の C19、run-24 の C28）。モデルと元のコードの対応を判定した実行はない。
- UTF-16 との違いは結果に影響しないという主張（run-18 の C18）。試した入力はすべて ASCII だった。
- 出力が変わるのは以前誤っていた入力だけだという主張（run-26 の C67）。修正の前後で publish の出力を比べた実行はない。
- 書き直した規則の意味は元と同じだという主張（run-18 の C2）。

筆者はこれらを、AI が推論やコードの読みから述べたことを、検査の結果と同じ文体で並べたものと読んだ。
読み手が文面から、検査で確かめた主張と見分けるのは難しい。

### 2. 全称の表現が、有限の検査やモデルの証明に付いている

「任意の」「どの入力でも」「必ず」「全」のような表現の主張について、実際に判定した範囲を並べると次のようになる。

- run-25 の C10「どの入力でも、AST を返すかそのモードの SyntaxError を投げる」：実際は、語彙40個で長さ3まで、語彙29個で長さ4までの全列挙と、長さ5〜10のランダム40万件である。同じ発言に、この範囲が書いてある。
- run-18 の C10「出力側でエスケープした文字列は…必ず元に戻る」：実際は Lean のモデルの定理と、6文字の語彙で長さ6までの実コードの往復である。
- run-23 の C30「任意の文字列で parse(publish(s)) は元の s に戻る」：実際は Z3 のモデルで長さ5まで、実コードで4文字の語彙の長さ9までである。同じ項目に「長さ無制限の証明ではありません」とある。
- run-19 の C55、C56「全 fixture」：実際に使った fixture は6ファイルのうち4ファイルだった。

多くの場合、同じ発言のどこかに実際の範囲が書いてあった。
筆者は、主張の文だけを抜き出して読むと範囲が落ちる書き方だと読んだ。
同じ発言に範囲が書いてあるかどうかは、表2の「同じ発言にある範囲」の列で確かめられる。

### 3. 主張した性質と、実際に判定した条件が違う

主張の文が述べる性質と、対応する実行が判定していた条件に差がある行があった。
作業者が備考に書いたものから挙げる。

- run-22 の C21「回避策を当てて再実行したところ、違反は0件」：根拠の実行は、ライブラリの publish の代わりに、検査の中で差し替えた publish を使っていた。
- run-26 の C91「publish した文字列を読み戻すと同じ構文木になる」を、違反のない性質の一覧に挙げている。同じ実行で、読み戻せないもの（PublishReparses）は29件の違反だった。読み戻せた入力だけを比べる条件だったためである。
- run-25 の C13、run-22 の C10「traverse が全ノードを1回ずつ訪問する」：run-25 の検査は `meta` の下のノードを数えない。run-22 の検査は訪問の合計の回数を比べるもので、ノードごとの回数は比べていない。
- run-20 の C28「長さ8以下の全87万ケース＋帰納的な論証」：帰納的な論証にあたる実行はない。
- run-21 の C21「型の意味は変わらない」：判定した実行はない。近い実行は構文木の完全一致を比べたもので、そこでは不一致が出ていた。

### 4. 対応する実行があった主張の多く

200行の多くは、対応する実行があった。
その実行の記録された結果は、主張の文が述べる結果（違反0件、ビルドの成功など）と同じであることが多かった。
ただし、筆者はこれを全行で突き合わせて数えてはいない。
また、記録された結果と主張が同じでも、その実行の範囲が主張の範囲と同じとは限らない（上の2と3）。
