# 探索的分析3：主張の台帳と発見の台帳

この分析は事前登録（`preregistration.md`）に含まれていない。
探索的な分析として、事前登録した分析とは分けて報告する。
判定（仮説の支持、手法の良し悪し）はしない。
台帳は、被験側の原文と成果物の対応づけにとどめる。

## 目的

実験者の方針（2026-11-16）により、「形式手法か否か」の分類はしない。
保証は、手法の性質ではなく、主張と証拠の組（対象、オラクル、範囲、仮定）として扱う。
この分析は、その組と、被験側が報告で述べた内容とのズレを記録する。

## 報告での条件の扱い

2026-11-16、台帳の結果を見た後に、実験者と分析者が次のとおり決めた。

- **条件A2 を「バイブ形式手法」の代表とする**：記事は、バイブ形式手法を、形式手法の知識がなくても AI との対話だけで形式手法を使うものと定義している。不慣れな人の依頼として自然なのは、道具を指定しない「形式手法で検証してください」（A2）である。
- **条件B は、手順書を渡した場合として並べる**。
- **条件A（道具を Lean 4 に限った場合）は補足とする**。A の結果も省かずに載せる。
- **条件の間で件数を合算しない**。A と A2 は、依頼の文面と使える道具が違う。
- この決定は結果を見た後に行った。A2 には、自作のオラクルによる断定や既存のテストの期待値の書き換えなど、記事の主旨に関わる事例が多い。代表にした理由は、記事の定義に合うことであり、事例の多さではない。
- A についての記述は、評価ではなく事実の形にとどめる（例：「道具を Lean に限った3回では、検証の範囲が狭く、不一致の報告も少なかった」）。

## 対象と方法

- 対象は系列1の条件A、A2、B の9回（run-02〜run-10）である。
- 範囲は固定発言を受け取る前の発言で、run-10 は記録の最後までとした。訊かれなければ何が主張されたままになるかを見るためである。
- 符号化の規則は `analysis/exploratory-3-ledger-rules.md` にある。記録を読み直す前に固定し、その後の変更は末尾の「変更の記録」に書いた（変更1、変更2、変更2の明確化、変更3）。
- run ごとに1体の作業者（サブエージェント）が台帳を作り、規則を変えるたびに、関わる行を読み直した。
- 論点に関わる行（限定の及び方、不一致の断定、逆向きの断定、両論、不一致の行）は、別の作業者が、元の符号を見ずに独立に符号化し直した。
- 発見は、分析者が run をまたいで束ねた（`exploratory-3/findings-bundled.tsv`）。

項目ごとの一致率は、両方が「なし」とした行が多いため高く出る。
「いずれかの項目で超えたか」で比べると、どちらかが「超えた」とした72行のうち、両方が「超えた」としたのは45行だった。
元の作業者だけが「超えた」としたのは25行、独立の作業者だけが「超えた」としたのは2行である。
食い違いの多くは、範囲と仮定について、元の作業者が「超えた」、独立の作業者が「なし」とした行だった。
食い違った行は、どちらにも寄せずに残し、集計では「両方」と「どちらか」を並べる。

## 限定

- 9回、1モデル、1リポジトリである。対象はパーサーで、往復の検査と相性が良い。
- 判定役は「お任せします」と固定発言しか送らないので、人間がオラクルを与えた場合の挙動は、この9回からは分からない。
- 規則は、台帳を作り始めた後に3回変えた。変えるたびに、変える前に読んでいた範囲を記録した。
- 独立の符号化の対象は、元の作業者が論点の印をつけた行だけである。印の漏れは、独立の作業者には拾えない。
- 元の作業者が1つの文を複数の行に分けた場合、独立の作業者には分ける前の文しか渡さなかった。分けた行の食い違いには、行の切り方の推測の違いが混ざっている可能性がある。
- 表1の不一致側の列は、行の単位の符号であり、変更3（入力の形で束ねる、条項の優先）を当てる前の値である。欠陥の断定は、発見の単位の表2を主とする。
- 表3の「書き加えた行」「書き換えた行」は、束ねる前の発見の行で数えている。run-09 の書き換えは、同じ3件が2行（F2a、F2b）に記録されている。
- 呼び出しの番号（call）は、作業者によって数え方が違う。行の照合は id で行った。

## 確かめられなかった点

run ごとの `boundary.md` に書いた。
主なものは次のとおりである。

- モデルと実コードの忠実さ。どの run でも、機械的な照合はしていない。
- 被験側が書いた列挙のプログラムが、宣言した範囲を本当に覆っているか。件数が理論値と一致することだけを確かめた run がある。
- 乱数を使った検査の生成内容。seed の記録がない。
- 実コードでの再生は、被験側が行ったかを記録から読んだ。ハーネス側では再生していない。
