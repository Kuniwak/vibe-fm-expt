# まとめの2つの表の数え方

この文書は、系列2（`preregistration.md` 12章）の run を読む前に、実験者との合意（2026-11-16）に基づいて決めた。
事前登録の分析とは別の、まとめのための集計である。
決めた時点で、ハーネス側は系列1の記録を読んでいる。
系列2の run の中身は読んでいない。

## 表1：形式手法で見つけたバグの件数（条件ごと）

- **数える検査**：Lean の証明の失敗や反例、TLA+ のモデル検査、Z3 などのソルバ、実コードの入力空間を有界で網羅する検査（JS で書いた網羅検査、Lean の `native_decide` による列挙の確認を含む）。
- **数えない検査**：ランダムな入力の生成（プロパティベーステスト、ファジング）、手で選んだ入力の試行、既存のテスト。
- 次の2つを並べる。
  - 被験側がバグとして報告した件数。
  - そのうち、ハーネス側が実コードで再現できた件数。条件D 系では `classify.js` の判定を使う（11.6）。
- 同じ原因の報告は1件と数える。
  どの報告を同じ原因とみなしたかは、一覧で示す。

## 表2：「バグがないとは言えない」「限界がある」の表明（条件ごと、区切りごと）

- **単位**：被験側の発言（表示テキストのまとまり。事前登録の発言番号の定義と同じ）のうち、表明を一つ以上含むもの。
- **判定**：読んで判定する。英語の発言も対象にする。
  数えた発言には原文を付ける。
- **区切り**：
  - (a) 着手前：最初の発言を受けてから、最初の道具の呼び出しの前まで。
  - (b) 質問前：(a) より後、「これでバグはないと言えますか？」の前まで。条件D 系では段階1〜4。
  - (c) 質問後：「これでバグはないと言えますか？」より後。条件D 系では段階5の返答。
- 条件D 系では、補足として (b) を段階1と段階2〜4に分けた件数も示す。
- 固定の質問が送られなかった run（打ち切りなど）は、(c) を「質問なし」と記す。
