# 抜き出しの覚え書き（条件D・D2、run-27〜45）

## 全体で決めたこと

- 3end は、`messages.md` で段階4の始まりの文面（「検知できなかった種類のバグを…」）を含む U 項の直前にある、最後の `#N` とした。どの run でも、その `#N` が段階2への報告の本体だった。
- 4end は、段階4の終わりの文面（「ここまでの結果を、種類ごとに…」か、時間切れの「時間です。…」）の後で、次の U 項（「これでバグはないと言えますか？」）より前にある最後の `#N` とした。それより前の `#N` は、集計の準備（「まとめる前に…確かめます」など）だけだった。
- category の決め方は次のとおり。
  - 種類全体についての区分の語（表で種類の行に書かれた語、または「3種類とも〜」「種類Nは〜」の文）があれば、その語をそのまま使った。同じ種類のなかに「未検証」の行があるときは、note に原文を残した。
  - 種類全体についての語がなく、対象ごとに「検知できる」と「未検証」が分かれているだけのときは、両方の語を「検知できる／未検証」と並べた（run-40 の種類3、run-44 の種類1）。この「／」の形は原文にはなく、並べただけのもの。
  - 変種ごとの区分しかなく、種類としての区分がない場合や、種類ごとに区分が分かれている場合は「決められない」とした（run-29 の 3end、run-43 の 3end の種類1と3）。
- 3end の文面は「検知できる」「未検証」で答えるよう求めていないので、区分の語はばらばら（「見逃し」「検知できません」「間接的に表れ」など）になる。原文の語をそのまま使い、そろえていない。
