読んだもの：`ROOT/prompts/`（d-stage2・d-stage4・d-stage4-done・d-stage4-timeout）、各 run の `analysis/messages.md`・`analysis/operator.md`・`record/metadata.txt`、run-28・30・32 の `record/driver-summary.json`（run-30 には無かった）、run-30 の `record/` のファイル一覧（`snapshot-S3-timeout.err` というファイル名だけを見た。中身は読んでいない）。

## 全体の方針

- 3end は、段階4の始まりの文面（`d-stage4.txt`）を含む `U` 項の直前にある `#N` とした。全 run で、その直前の項は被験側の発言だった。
- 4end は、段階4の終わりの文面（done または timeout）を含む `U` 項から次の `U` 項までの被験側の発言のうち、種類ごとの判定を書いた発言とした。前置きの発言（「まとめる前に…集計します」など）は除いた。
- 1つの種類の中で範囲や経路ごとに「検知できる」と「未検証」を分けて書いている場合は、どちらか一方を選ばず、category を「検知できる／未検証」とした。どちらの語も原文の語であり、範囲は note に書いた。種類の行に原文で1つの語が書かれている場合（run-41 の種類1「検知できる（下の範囲のみ）」）は、その語をそのまま使った。
- 3end では、被験側は「検知できる／未検証」の二分を頼まれていない。そのため、被験側が種類ごとに書いた語（「見逃しました」「まったく検知できません」など）をそのまま category にした。変種ごとにしか語がなく、種類単位の語がないものは「決められない」とした。
- quote の中の「…」は、私が途中を省いた箇所。
