# run-28（D2）の準備メモ

この run の段階4は時間切れで終わったが、写しは `S3`（段階5の後）で、`S3-timeout` ではない。
呼び出し番号は `analysis/commands.md` に合わせた（記録から重複を除いて数え直し、一致を確かめた）。

## レシピ

### S1（`recipe-S1.sh`）

- 次の3つを含めた。
  1. `/tmp/pv/prop.js`：call 20 のシード6つのループ。
  2. `tests/test_properties.js -g generated`：call 30 のシード5つのループ。
  3. `npm test`：call 29。
- 迷った点：`/tmp/pv/prop.js` は探索用の書き捨てのスクリプトで、リポジトリには入っていない。
  ただ、#14 の「生成・変異させた入力は延べ約100万ケース（シード違いで複数回）すべて成立」は、call 20 の 6 × 160,000 = 960,000 件にあたる。
  報告で検証として述べているので含めた。
- call 29 と call 30 の `grep` の絞り込みは外した。
  call 20 の `| head -4` は残した。
- S1 の検査はどれも同期的に動く。
  終わらない変種では返ってこない（被験側も段階3でこれを確かめた、#30）。
  そのため、レシピの側で `timeout` を足した（prop.js は1シードあたり120秒、mocha も120秒、npm test は900秒）。
  被験側の検査の内容は変えていない。
- 基準状態でも、prop.js はシード 99991 で `()=>*!=[]` の違反を2行（2モード）出す（call 20）。
  そのため、基準の出力は空ではない。
- `npm test` は先に lint と build を実行し、カバレッジ100%の閾値もある。
  参照変種が lint に通らない場合や、覆われない分岐を足す場合も、失敗（終了コードが非0）になる。

### S3（`recipe-S3.sh`）

- 被験側が最終版で変種を確かめたときのコマンドに沿った（`/tmp/mut/run2.sh`）。
  - `timeout 900 npx mocha tests/test_properties.js`
  - `timeout 600 npx mocha 'tests/test_*'`
- `npm test` は含めなかった。
  mocha の部分は2つ目と同じで、残りは lint、カバレッジの閾値、tsc である。
  被験側も変種の確認には使っていない。
  ただし #48 は「変種なしの状態で npm test は通ります」と述べている。
  含めるかはハーネス側の判断に任せる（原文は call 82）。
- 表との照合テストは、既知の違反の一覧 `tests/properties/known-precedence-violations.txt`（2,931パターン）に載っていない違反でだけ失敗する。
  パターンは、オペランドを `X` に置き換えた入力と、parse の結果で決まる。
  参照変種の違反が、すでに一覧にあるパターンに落ちる場合は検知されない。
  これは被験側の検査の仕様どおりである。
- 種類3の変種があると `tests/test_*` は終わらず、`timeout 600` で止まる（#40）。
  `test_properties.js` は、worker の5秒の制限で報告を出して終わる。
- 終了コード：どちらのレシピも、各段階の終了コードのうち最初の非0を返すようにまとめた。
  被験側は、それぞれを別のコマンドとして実行していた。
