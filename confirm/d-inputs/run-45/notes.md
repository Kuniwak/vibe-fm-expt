- 被験側は call 24 で npm test の出力を捨てて終了コードだけを表示した。レシピでは「N failing」を拾えるよう、出力を出したままにした。
- 被験側は check.js の出力を out4.json に書いてから読んだ。レシピでは標準出力に出す（中身は同じ JSON）。

- esc.js は Math.random で入力を作る。基準に違反行があると、変種がなくても種類（数字を除いた形）が実行ごとに変わり、誤って「検知」になる。記録では、S1 の木での違反は0件だった。
- npm test は lint、nyc のカバレッジ 100% の閾値、tsc を含む。変種によっては、テストが落ちなくてもこれらで非0になり得る。被験側が #5 でこれらを含めて「通っています」と述べたので、そのまま含めた。
- 時間制限：S1 時点の検査には、終わらない入力への時間制限がない。変種で check.js が止まると、全体の 5400 秒まで戻らず、後ろの esc.js は実行されない。順序は被験側（call 24）に合わせて npm test → check.js → esc.js にした。npm test 内の tests/test_no_hang.js が先に止まる可能性もある（段階3の t3_hang では mocha が `{myNum}` で止まり、600 秒で打ち切られた。#15）。

- 抜き出したのは、被験側が発言（#2、#5、#15、#22、#23）で違反として挙げた入力と、#5 で「上の反例9件」として回帰テストに加えた入力（call 16・23）である。
