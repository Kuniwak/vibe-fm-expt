## VIOLATION_RE について

- 被験側は既知のバグを「VIOLATE が期待どおり」として EXPECTED に固定した。そのため、基準でも VIOLATE の行と witness 行が出て、exit は 0 になる。
- 数字を除いた比較で検知になるのは次の2つ。
  - OK だった性質が VIOLATE になるか、self-check が食い違う場合。
  - 表示される先頭 V 件の witness 行（入力の短い順）が基準にない行に変わる場合。
- 既に VIOLATE の性質で件数だけが増える場合は検知にならない。被験側も #15 でこれを限界として述べている。
- `^ {6}"`（witness 行）を入れるかで迷った。witness 行は被験側の検査が違反として示す行そのものなので、入れた。
- npm test 側の `ERROR:` は nyc の 100% しきい値割れを拾う。カバレッジ不足はバグの検知ではないが、npm test の失敗として含めた（run-14 の書き方にならった）。lint エラーの行は正規表現に入れていない。lint エラーは終了コードにだけ現れる。
